## v0.1-baseline 读数(2026-09-10)

- **增益存在但分层**:事实题 RAG 4.08 vs 裸模型 3.71(+0.37);推理题 3.66 vs 4.17(-0.51)——
  推理题被检索拖累,根因是误拒:29 道误拒中 28 道 gold 不在 top-5,模型看到"邻而不准"的资料后诚实拒答
- doc 口径 87.5% vs chunk 口径 64.4%:找对文档、找不到段落,是全部下游问题的源头
- 正确拒答率 97.5%:40 道无法答题 39 道正确拒答;唯一未打 refused 标志的(unans-023)答案
  实质是"资料未提及具体工具",引用了语料仅有的 TechEmpower 信息,无编造
- faithfulness 0.961:答出的内容 96% 有资料支撑

## v0.2-hybrid 读数(2026-09-10)

- **全面超越基线**:chunk recall@5 +18.8pp、MRR +13.5pp、正确性 +0.49、误拒率 18.1%→7.5%、
  正确拒答率 100%(40/40),faithfulness 持平 0.96
- **推理题翻身**:3.66→4.12,与裸模型(4.17)基本打平——检索不再拖累,v0.1 的"邻而不准→误拒"链路被切断
- 事实题 4.58 vs 裸模型 3.71:RAG 增益扩大到 +0.87
- 改动仅检索层(BM25 中文 bigram + RRF,生成与 prompt 零改动),指标提升可归因于检索
- 剩余误拒 12/160,主要是个别问题表述与 gold chunk 词汇重合度低的召回死角 → v0.3-rerank(粗排 20 精排 5)与 v0.4-rewrite(多查询扩展)的攻击面

## v0.3-rerank:环境不可行,搁置(2026-09-11)

- 检索层验证在本机(CPU + 电池供电)运行 75+ 分钟未完成:rerank 每题 20+ 秒,
  比 hybrid(毫秒级)慢两个数量级,微基准(0.14s/2 对)严重低估了 512 token 长上下文的真实成本
- 代码与 `RETRIEVER=rerank` 开关保留,Phase 6 若部署到 GPU 机器可重启验证
- 当前最优版本保持 **v0.2-hybrid**;优化主线转向 v0.4-rewrite(LLM 查询扩展,预估每题 +2s)

## v0.3-rerank 读数(2026-09-11,接电源后全量跑出)

- **检索层大幅提升**:chunk recall@5 83.1%→90.0%,MRR +10.8pp,doc 口径 98.8%
- **端到端仅小幅转化**:正确性 4.41→4.49(+0.08),事实题 +0.16、推理题持平;
  误拒 7.5%→5.6%;正确拒答 100%→97.5%(唯一未拒答是 unans-023 软拒答,答案明说
  "资料未提及具体工具"并引用语料仅有的 TechEmpower 信息,无编造)
- **检索提升未能全额转化的解释**:MRR/排序增益对"top-5 已够生成用"的题是冗余的,
  端到端增益主要来自 recall 修复的 11 道题
- **成本**:CPU 每题 +6.3s(检索 0.2s→6.5s);电池供电下更差(曾 >20s/题)
- **结论:CPU 部署默认 v0.2-hybrid(质量/延迟最优平衡);v0.3 代码与开关保留,
  GPU 环境或检索精度优先场景启用**

## v0.4-rewrite:负结果,不入主线(2026-09-11)

- 检索层全量 160 题(端到端未跑,检索层已出局):**平权 RRF 融合 recall@5 74.4% /
  MRR 0.579**;原查询 4 倍加权后 **80.0% / 0.621**——均低于 v0.2 hybrid 的 83.1% / 0.656
- 机理:3 个 LLM 变体对"相关但不准确"chunk 的共识分轻易压过原查询 rank-1
  (3×1/61 > 1/61),变体把语料热词 chunk 顶进 top-5;加权只能缓解不能逆转
- 结论:本语料(问题表述与文档语言同域)下,单查询 hybrid 已是最佳信号,LLM 变体
  增噪大于扩召回;变体的可能价值在"扩展候选池供精排"(与 v0.3 组合),CPU 场景不划算
- 成本参考:每题 +1.8s(LLM 改写 1.4s + 多路检索);10 题探测会漏判(小样本 0.9/0.77),
  全量才暴露——探测只防超时,不做质量结论
- 代码保留(app/rewrite.py,RETRIEVER=rewrite)

## v0.5-chunking:切块不是瓶颈,现役方案保持(2026-09-11)

- doc 口径三方对比(160 可答题,chunk 口径因 id 体系不同不可比):
  heading(现役) 94.4%/MRR 0.845 | fixed-512-50 **95.6%/0.869** | parent-child 95.0%/0.829
  ——三案差距 ≤1.3pp,切块方案对"找对文档"影响甚微
- parent-child 50 题快评(唯一有生成侧假设的方案,整节上下文喂生成):
  正确性 4.64 vs v0.2 同子集 4.62,打平;事实 +0.08/推理 -0.07;
  faithfulness 0.947 vs 0.976(整节上下文略增不实声明空间);误拒 5.0% vs 2.5%
- **结论:heading-512-50 保持现役**;fixed 的 +1.3pp doc 增益不值得丢失标题结构;
  parent-child 生成侧假设未兑现。Phase 4 优化循环就此收官
- 附注:parent-child 的 chunk 口径指标显示 0 属度量体系错位(父块 id ≠ gold 子块 id),
  以 doc 口径与端到端为准

## 跨模型一致性验证(2026-09-11)

- 30 条抽样(种子 7,事实15/推理9/无法回答6)由独立第三方模型盲评(judge 分数隐去防锚定),
  与 Qwen judge 对比(可答题 24 条,judge 不给无法答题打分,后者由正确拒答率覆盖)
- **±1 分一致率 100%(24/24),完全一致 71%(17/24),Pearson r=0.886**
- 三个低分样本(误拒题)被两个模型独立同判 1 分——失败样本识别完全一致,非巧合
- 均分差 +0.30(跨模型 4.42 vs judge 4.12):第三方模型整体略宽,但排序高度一致
- **结论:judge 打分可信,自评偏宽的嫌疑基本排除**;RAG 答案质量结论不因评分者而变
